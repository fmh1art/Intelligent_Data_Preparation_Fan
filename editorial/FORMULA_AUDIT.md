# 公式与算术核查

日期：2026-09-09。范围为全部正文数学表达式、图3的金额计算及表8的派生数值。正文只有1个编号公式，是本文的统一分析表达式，不是某篇原论文的优化算法。核查后保留目标形式，修订约束语义与适用条件；另发现Auto-Tables原文Hit@k记法与公开实现不一致，已按实现补充说明。未发现示例算术或表8换算错误。

## 式（1）：目标与约束

| 核查项 | 判断及修订 |
|---|---|
| 最大化方向 | 正确，但需统一效用方向。明确效用是越大越优的标量；若评价量为损失，则使用负损失。预算约束中的成本不必再从效用中相减；原式属于预算约束优化，并非加权多目标优化。 |
| 输出与过程约束 | 原式仅用最终数据满足硬约束，无法表达前文的访问范围约束。两个流程可能输出相同表，却访问不同来源。增加执行过程Exec及记录τ，使硬约束检查最终输出与实际过程。 |
| 执行结果类型 | 明确D′可为单表或多个数据对象；Exec返回输出及记录，D′仍是P应用于原始数据的结果。 |
| 成本参数与量纲 | 显式标注数据、任务条件，固定环境及计量协议。预算非负，分别与对应成本采用同一单位，不把人工分钟、执行秒数或货币直接相加。 |
| 优化值与最优流程 | max用于表达最优目标值/优化问题，当前正文没有用它定义最优流程P*，因此无须改成argmax。执行失败和不终止流程不属于可行解；不宣称可行解一定存在或全局最优一定可得。 |
| 下游学习 | 效用隐含固定训练和数据划分协议；选择阶段用验证信息，测试真值留出。验证损失与训练损失的作用区分与[DiffPrep原文§2.3、§3.3](https://arxiv.org/html/2308.10915v1)一致，但本式没有替代其双层优化。 |
| 随机性及总成本 | 明确为固定随机性和交互条件下的单次运行记法；未声称期望预算或概率保证。候选生成、训练及重试须按完整搜索协议另行累计，不能仅以最终流程的一次运行成本代表全部准备成本。 |

## 图3及§4.5：有限求和推导

设订单i的金额为aᵢ，退款事件集合为Rᵢ，数量为nᵢ，每个事件j的退款金额为rⱼ。订单键唯一，所有退款均关联保留的订单，每个事件只计一次，无退款的和为0。则正确总额为：

$$N=\sum_i\left(a_i-\sum_{j\in R_i}r_j\right)=\sum_i a_i-\sum_j r_j.$$

左连接后每个订单有max(1,nᵢ)行。若逐行重复减退款后汇总，则错误路径的结果为：

$$W=\sum_i\max(1,n_i)a_i-\sum_j r_j,\qquad W-N=\sum_i[\max(1,n_i)-1]a_i.$$

本例a=(100,80)、n=(2,0)，因此重复计入量为100，正确净收入为180−30=150，错误结果为250。直接展开为(100−20)+(100−10)+(80−0)=250；先聚合则为(100−30)+(80−0)=150。图中等式与正文一致，无须重绘。

将第二笔退款10改为15，正确值变为145，错误值变为245；重复计入量仍为100。对三个订单的金额分别取{0,80,100}、每单退款数量分别取{0,1,2}，各退款依序取10、20，另用SQLite穷举729种组合，聚合结果与上述恒等式、重复计入量公式全部一致。穷举用于数值交叉检查；有限和推导给出该假设范围内的一般理由。

正文补充退款事件互不重复且存在所属订单的前提；回退表述改为本例采用的一条有效修订路径，不声称它是唯一修复方式。订单键唯一只约束该中间表示；总额相等仍无法排除客户归属错误或相互抵消的金额错误，二者都不是完整正确性的充分条件。

## Hit@k：原文记法与实现差异

[Auto-Tables正式论文§5.1，第3400页](https://www.vldb.org/pvldb/vol16/p3391-he.pdf)将单任务Hit@k写为对前k个候选匹配指示量的求和。若两个候选都正确，该和为2，不能直接作为取值0或1的任务命中事件。这是原文记法存在的歧义，不能照抄为一般定义。

[作者公开evaluate.py](https://github.com/LiPengCS/Auto-Tables-Benchmark/blob/main/evaluate.py)的compute_hit_at_k在第一个匹配处将当前及之后的Hit@k置1并break，实际实现是至少一次命中。其is_hit比较标注的算子和参数序列，同时接受列出的alternative_label，不执行任意候选程序来验证输出等价。由代码可写为：

$$h_k(T)=\mathbf{1}\{\exists i\leq k:\operatorname{Match}(\widehat{P}_i,\mathcal{G}_T)\},\qquad \mathrm{Hit}@k=\frac{1}{N}\sum_{T}h_k(T),$$

其中N为任务数，𝒢_T为该任务已列出的流程真值。正文§5.3明确采用这一实现口径；表8保留原论文报告的0.570和0.750，二者相差0.180。未重新生成候选，也没有仅凭阅读代码声称重现原表分数。
