# 图3：多表准备流程的错误传播、验证与回退

用途：中文学术综述中的作者构造示例；不是任一论文实测结果。横向 3:2 高分辨率，白底，深蓝与青绿主色，橙红只标记错误与回退，细线数据库/表格/放大镜/检查盾牌/历史版本图标。元素较丰富但层次清晰，所有文字必须精确且清晰。风格保持论文专业性，无卡通人物、机器人或装饰性3D。

布局：左侧两张输入表，中间上方错误分支，中间下方修订分支，右侧独立验证与结果。顶部小标题“多表汇总中的重复计入”。顶部任务卡“目标：按客户汇总净收入；订单金额仅计一次”。

输入表 A：订单 O，三列“订单 / 客户 / 金额”，两行“o1 / A / 100”“o2 / A / 80”。输入表 B：退款 R，两列“订单 / 退款”，两行“o1 / 20”“o1 / 10”。旁注：金额单位一致；无退款记0。

上方橙红错误路径：先按订单做左连接（数据库 join 图标）→中间表（三列“订单 / 金额 / 退款”，三行“o1 / 100 / 20”“o1 / 100 / 10”“o2 / 80 / 0”）→逐行相减再按客户求和→红色结果卡“A：250（错误）”。在重复的100旁用小圈/浅红高亮说明“订单金额重复计入”。所有步骤均能执行；不要把错误画成语法报错。

下方青绿正确路径：退款先按订单聚合（分组图标）→小表“o1 / 30”→与订单左连接→小表（三列“订单 / 金额 / 退款”，两行“o1 / 100 / 30”“o2 / 80 / 0”）→相减并按客户汇总→绿色结果卡“A：150”。显示正确式“(100−30)+(80−0)=150”。

右侧验证卡，标题“独立检查”，内容“连接后订单键应唯一”“净收入总和 = 180−30 = 150”。从错误中间表指向检查卡实线；检查卡向左回到“连接前的源表状态”画橙红回退弧线，标注“回退并先聚合退款”。验证检查来源是预先给定任务口径，非模型自评分。小脚注“示例假设退款可加，全部订单保留”。

底部细条将元素对应正文框架：“任务：结构转换（多表连接与聚合）｜状态：源表与中间表｜验证：粒度与总额不变量｜修订：恢复连接前状态”。

负面要求：不要出现正文外的金额、行、重复的流程箭头；不要画“直接连接→150”；不要把一对多连接本身标成违法；不要把最终客户键唯一当作足够验证；不要宣称搜索必然正确。颜色之外用标签与分支位置区分正误。
